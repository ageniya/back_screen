# 机器人背屏交付与使用手册

本文档面向交付、测试和现场使用人员，说明背屏的用途、启动方式、页面操作、真实数据条件与验收方法。

## 1. 背屏是什么

背屏是运行在 Pico 上的只读诊断界面。它不直接读取网页以外的数据，也不直接控制机器人；数据链路如下：

```text
Pico / Orin 的 ROS2 节点
        ↓
机器人背屏后端（订阅、整理、告警判断）
        ↓ HTTP API
背屏网页（状态、告警、日志、作业总结、3D 视图）
```

后端的职责是把不同电脑、不同消息类型的 ROS2 数据整理为稳定的背屏字段。前端只显示后端已经确认收到的数据。没有数据时显示 `--`，不使用模拟值冒充真实机器人状态。

## 2. 页面与操作说明

| 页面 | 用途 | 是否控制机器人 |
| --- | --- | --- |
| 状态 | 查看实时状态、资源、传感器在线情况和当前告警 | 否 |
| 告警 | 查看未恢复/已恢复告警及来源 | 否 |
| 日志 | 查看后端记录的诊断、状态变化和操作结果 | 否 |
| 作业总结 | 查看本次作业时间、能耗和结束原因 | 否 |
| 工具 → 3D 视图 | 只读显示机器人模型、关节姿态及异常部位 | 否 |

### 状态页按钮

- **一键诊断**：对后端当前已经收到的数据执行规则检查，不会让机器人动作。
- **确认已恢复**：仅确认/清除“已经恢复”的告警；不能消除仍然存在的硬件故障。
- **软件停止**：默认禁用。只有经过安全评审，并在后端设置 `ROS_ENABLE_CONTROL=true` 和真实停止服务后才可用。

> 机械急停必须始终以机器人实体急停按钮为准；背屏的“软件停止”不能替代急停。

## 3. 正式交付启动方式

正式版本不需要 `npm run dev`，也不需要在机器人上单独开 5173 端口。前端会打包进后端服务，生产环境只需启动一个服务：

```bash
sudo systemctl enable --now robot-back-screen-api.service
systemctl --no-pager status robot-back-screen-api.service
```

Pico 屏幕浏览器应打开：

```text
http://127.0.0.1:8000/
```

服务日志：

```bash
journalctl -u robot-back-screen-api.service -f
```

安装好服务后，现场也可以直接执行统一启动入口：

```bash
start-pico-back-screen.sh
```

它会启动背屏后端、等待 `/healthz` 通过，再打开全屏背屏；如果已安装视频服务，还会一并检查 `zj-media-play.service`。

### 当前 Pico 现场预览版的开机启动命令

如果 Pico 上还没有安装 `robot-back-screen-api.service`，才使用下面的开发/预览方式。两个终端都要保持运行；关闭终端会停止对应服务。

#### 0. 先启动机器人嵌入式数据源

如果需要上肢关节和 TCP 数据，先确认嵌入式 SDK 已运行。没有运行时，背屏后端无法凭空产生关节数据。

```bash
cd /home/nav01/CodeFiles/sdk/zjhrobotsdkreleaseproject
sudo ./run.sh
```

另开终端加载 Pico 的 ROS 2 环境并验证：

```bash
source /etc/nav01/Middleware.env
source /opt/ros/humble/setup.bash
echo "$ROS_DISTRO $ROS_DOMAIN_ID $RMW_IMPLEMENTATION"
ros2 topic info /zj_humanoid/upperlimb/joint_states
ros2 topic echo --once /zj_humanoid/upperlimb/joint_states
```

预期环境为 `humble`、Domain `72`、`rmw_cyclonedds_cpp`；关节话题必须有发布者并能收到一帧。若 SDK 日志出现 `expect(26) act(4)`，说明 EtherCAT 从站未完整识别，关节值即使有话题也不能作为真实姿态验收。

终端一：启动后端（ROS 订阅和 HTTP API）：

```bash
cd /home/nav01/back-screen-preview
source /etc/nav01/Middleware.env
source /opt/ros/humble/setup.bash
export PYTHONPATH="/home/nav01/back-screen-preview:/home/nav01/back-screen-preview/.python-packages:$PYTHONPATH"
export TELEMETRY_MODE=ros
export ROBOT_MODEL=WA-T
export ROBOT_NAME=zj_humanoid
export ROS_BATTERY_TOPICS=/web/battery_info
export ROS_ODOM_TOPICS=/web/odom_info
export ROS_LIDAR_1_TOPIC=/scan
export ROS_JOINT_STATES_TOPIC=/zj_humanoid/upperlimb/joint_states
export ROS_LEFT_TCP_TOPIC=/zj_humanoid/upperlimb/tcp_pose/left_arm
export ROS_RIGHT_TCP_TOPIC=/zj_humanoid/upperlimb/tcp_pose/right_arm
export ROS_UPPERLIMB_STATE_TOPIC=/zj_humanoid/upperlimb/uplimb_state
export ROS_DEPTH_CAMERA_TOPIC=/zj_humanoid/sensor/realsense_head/depth/image_rect_raw
export ROS_CAMERA_TOPIC=/zj_humanoid/sensor/realsense_head/color/image_raw
export LOCAL_RESOURCE_SOURCE=pico
/home/nav01/back-screen-preview/.python-packages/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
```

终端二：启动前端静态页面：

```bash
python3 -m http.server 5173 --bind 127.0.0.1 --directory /home/nav01/back-screen-preview/web
```

浏览器打开：

```text
http://127.0.0.1:5173/?api=http://127.0.0.1:8000/api/v1
```

启动后先检查：

```bash
curl http://127.0.0.1:8000/healthz
curl http://127.0.0.1:8000/api/v1/robot/snapshot
```

`healthz` 应显示 `telemetryMode: "ros"`、`dataReady: true`，型号应为 `WA-T`。

### 正式部署前配置

配置文件为：

```text
/etc/robot-back-screen/env
```

最小实机配置示例：

```bash
TELEMETRY_MODE=ros
ALARM_PERSIST_SECONDS=5
ROS_ENABLE_CONTROL=false
ROS_BATTERY_TOPICS=/web/battery_info
ROS_ODOM_TOPICS=/web/odom_info
```

修改后重启服务：

```bash
sudo systemctl restart robot-back-screen-api.service
```

启动服务前，systemd 会加载 Pico 的 `/etc/nav01/Middleware.env` 和 ROS2 Humble 环境。两台机器必须位于同一 ROS Domain；当前现场使用：

```text
ROS_DISTRO=humble
ROS_DOMAIN_ID=72
RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
```

## 4. 开发联调方式（仅开发使用）

开发时前后端可分开运行：

```bash
# 终端 1：后端
cd robot-back-screen
source .venv/bin/activate
uvicorn robot_back_screen.main:app --host 127.0.0.1 --port 8000 --reload

# 终端 2：前端
cd robot-back-screen/frontend
npm run dev
```

浏览器打开：

```text
http://127.0.0.1:5173/?api=http://127.0.0.1:8000/api/v1
```

这套 `5173 + 8000` 仅用于开发。交付到机器人后应使用上一节的单服务模式。

## 5. 后端检查工具

| 地址 | 用途 |
| --- | --- |
| `/` | 背屏正式页面 |
| `/healthz` | 后端是否运行、是否收到 ROS 数据 |
| `/monitor` | 自动刷新显示后端当前收到的真实话题数据 |
| `/docs` | 接口文档；适用于接口调试，不是用户日常页面 |
| `/api/v1/robot/snapshot` | 当前统一状态 JSON |
| `/api/v1/alarms` | 当前告警 JSON |

例如，在 Pico 上检查：

```bash
curl http://127.0.0.1:8000/healthz
```

若浏览器显示“接口离线”，优先执行：

```bash
systemctl status robot-back-screen-api.service
curl http://127.0.0.1:8000/healthz
```

## 6. 当前数据来源与验收口径

| 数据 | 主来源 | 正常判断 |
| --- | --- | --- |
| Orin CPU、内存、磁盘、GPU、温度 | Orin resource 诊断话题 | 后端收到值并显示一位小数 |
| Pico CPU、内存、磁盘、温度 | Pico resource 话题或 Pico 本机资源 | 后端收到值并显示一位小数 |
| 头部、左腕、右腕相机在线 | Orin 相机图像话题 | 话题有实际发布帧 |
| 激光雷达 | `/scan` 等雷达话题 | 不只看发布者，必须能收到扫描帧 |
| 上肢关节、左右 TCP | Pico upperlimb 话题 | 必须有发布者且 `echo --once` 能收到值 |
| 手指、腕力 | Pico hand/wrist 话题 | 必须有实际非过期消息 |
| 电池 | BMS → `/robot/battery_info` → `/web/battery_info` | 必须有上游电池发布者 |
| 底盘位置、速度 | 底盘/导航 → `/navigation/odom_info` → `/web/odom_info` | 必须有实际里程计帧 |

### 现场接口与消息类型

| 页面数据 | 设备 | ROS 接口 | 消息类型 |
| --- | --- | --- | --- |
| 上肢关节角度 | Pico | `/zj_humanoid/upperlimb/joint_states` | `sensor_msgs/msg/JointState` |
| 左右 TCP | Pico | `/zj_humanoid/upperlimb/tcp_pose/left_arm`、`right_arm` | `upperlimb_msgs/msg/Pose` |
| 上肢运行状态 | Pico | `/zj_humanoid/upperlimb/uplimb_state` | `upperlimb_msgs/msg/UplimbState` |
| 手指关节 | Pico | `/zj_humanoid/hand/joint_states` | `sensor_msgs/msg/JointState` |
| 左右腕力 | Pico | `/zj_humanoid/hand/wrist_force_sensor/left`、`right` | `geometry_msgs/msg/WrenchStamped` |
| Orin 资源 | Orin | `/zj_humanoid/robot/orin_states/resource` | `robot_msgs/msg/Resource` 或 `navi_robot_msgs/msg/Resource` |
| Pico 资源 | Pico | `/zj_humanoid/robot/pico_states/resource` | `robot_msgs/msg/Resource` 或 `navi_robot_msgs/msg/Resource` |
| 资源诊断 | Orin/Pico | `*/robot/*_states/diagnostics_agg` | `diagnostic_msgs/msg/DiagnosticArray` |
| 电池 | Orin 转发 | `/web/battery_info` | `sensor_msgs/msg/BatteryState` |
| 底盘里程计 | Orin 转发 | `/web/odom_info` | `nav_msgs/msg/Odometry` |
| 激光雷达 | Orin | `/scan` | `sensor_msgs/msg/LaserScan` |
| 深度/彩色相机在线 | Orin | `/zj_humanoid/sensor/realsense_head/...` | `sensor_msgs/msg/Image` |
| ROS 日志 | 两端 | `/rosout` | `rcl_interfaces/msg/Log` |

逐项验收时必须执行：

```bash
ros2 topic type <话题名>
ros2 topic info <话题名>
ros2 topic echo --once <话题名>
```

只有 `Publisher count` 大于 0 且 `echo --once` 实际收到一帧，页面才应显示数值；只有话题名不能证明设备数据正常。

### 重要：话题名不等于数据可用

`ros2 topic list` 只能说明 ROS 图中出现过这个名字，不能说明硬件在发数据。验收必须同时检查：

```bash
ros2 topic info <话题名>
ros2 topic echo --once <话题名>
```

合格条件是：`Publisher count` 大于 0，且 `echo --once` 在合理时间内收到一帧真实数据。

## 7. 交付验收步骤

### 7.1 服务与页面

1. 开机后 Pico 自动打开背屏。
2. 触摸屏和鼠标均能切换状态、告警、日志、作业总结、工具页面。
3. 切出/切回 3D 页面后，可旋转、缩放、平移模型。
4. 后端 `healthz` 返回成功，`monitor` 刷新帧号递增。

### 7.2 真实数据

1. 在 Orin、Pico 各自加载正确 ROS2 环境。
2. 对每项计划展示的数据执行“话题信息 + 单帧接收”检查。
3. 背屏显示值与 `ros2 topic echo --once` 的值比对；数值显示保留一位小数。
4. 没有数据的字段必须显示 `--` 或“未接入”，不能显示演示数值。

### 7.3 告警

1. 断开一项可安全测试的数据源，确认告警在 `ALARM_PERSIST_SECONDS` 后出现。
2. 恢复数据源后确认告警自动标记为已恢复。
3. 点击“确认已恢复”后，确认告警从当前列表移除。
4. 短于 5 秒的瞬时波动不应留下历史告警。

### 7.4 安全

1. 确认 `ROS_ENABLE_CONTROL=false` 时，背屏不提供实际运动控制。
2. 若未来开放软件停止，必须单独验证 ROS 停止服务、权限、急停优先级和恢复流程。
3. 背屏故障、浏览器卡死或后端离线均不得影响实体急停。

## 8. 常见问题

| 现象 | 原因和处理 |
| --- | --- |
| 页面全是 `--` | 后端没启动，或 `TELEMETRY_MODE` 仍是 `mock`，或 ROS2 环境/Domain 不一致。先看 `/healthz` 和 `/monitor`。 |
| 有话题名但没有数据 | 看 `ros2 topic info` 的发布者数量；话题可能只是背屏后端创建的订阅名。 |
| `TYPE_SUPPORT` 报错 | 当前终端混入 ROS1 Python 路径。新开干净终端后加载 `/etc/nav01/Middleware.env` 和 Humble 环境。 |
| 电池显示 `--` | `web_state_relay` 只能转发；必须先有 BMS 节点发布 `/robot/battery_info`。 |
| 3D 不动 | 上肢 `joint_states` 或 TCP 没有真实发布。3D 不会用 `/fake/upperlimb/...` 伪造实机姿态。 |
| 雷达显示离线 | 驱动进程运行不代表有扫描帧；检查雷达供电、网线、设备 IP 和 `/scan` 实际输出。 |
| 触摸能按下但不切页 | 重启 Pico 背屏 Firefox；确认已部署当前前端版本。 |
