# 机器人背屏使用说明

更新日期：2026-11-11。本文描述当前仓库代码；机器人上是否已更新，以该机安装的文件和服务为准。设备 IP、实际话题前缀和消息状态以当前机器人环境为准。

## 1. 两台计算机分别运行什么

| 设备 | 功能 | 服务名 |
| --- | --- | --- |
| Pico | ROS2 数据订阅、状态整理、HTTP 接口和网页服务 | `robot-back-screen-api.service` |
| Pico | 在屏幕上全屏打开网页 | `robot-back-screen-kiosk.service` |
| Orin | 底盘运动门控、导航任务取消和急停后的软件复位 | `robot-motion-supervisor.service` |

Pico 后端可通过同一 ROS2 网络接收 Orin 的话题，Orin 无需再运行一个背屏 HTTP 后端。`ORIN_API_BASE` 是兼容已有 Orin HTTP 后端的可选配置，默认留空；`ORIN_IP` 仅用于地址展示，不会建立 HTTP 连接。

状态页的“复位”按钮会发出实际控制请求，其他页面主要用于查看数据。

## 2. 首次部署

以下命令均从项目根目录执行。机器人需已有 ROS2 Humble 及对应中间件；Pico 用户为 `nav01`，Orin 用户为 `naviai`。

在开发电脑构建网页，再将项目及生成的 `frontend/dist/` 一起复制到机器人：

```bash
nvm use 22
npm --prefix frontend ci
npm --prefix frontend run build
```

`nvm use 22` 适用于已通过 nvm 安装 Node.js 22 的电脑。机器人运行构建后的网页不需要 Node.js。`frontend/dist/` 不在 Git 中，仅拉取代码后需要构建或补齐此目录。

Pico 上执行：

```bash
bash deploy/install.sh pico
```

脚本将运行文件安装到 `/opt/robot-back-screen`，安装 `requirements.txt` 中的 Python 依赖，准备缺少的底盘消息接口，并启动 API 和全屏浏览器。安装依赖需要可用的软件源，或事先准备好的离线依赖。

脚本保留现有 `/etc/robot-back-screen/env`，备份旧运行文件，并停用旧的 `zj-humanoid-back-screen.service` 预览服务。备份在 `/var/backups/robot-back-screen/<安装时间>/`。

保持底盘静止，在 Orin 项目目录执行：

```bash
bash deploy/install.sh orin
```

脚本确认底盘连续静止后，安装复位主控到 `/opt/robot-back-screen-control`，备份并修改底盘三路运动入口的重映射，重启实际底盘服务，再启动主控。备份在 `/var/backups/robot-back-screen-motion/<安装时间>/`。安装不会自动复位或恢复旧任务。

背屏脚本不负责启动整套上肢 SDK、底盘硬件、相机和雷达驱动；这些数据源由机器人中间件提供。

## 3. 日常启动、关闭和刷新

安装过服务后，在项目根目录一键启动：

```bash
# Pico：后端和全屏网页
bash deploy/start.sh pico

# Orin：复位主控
bash deploy/start.sh orin
```

没有源码目录时，可直接使用下表：

| 操作 | 在对应机器人终端执行 |
| --- | --- |
| Pico 打开背屏和后端 | `sudo systemctl start robot-back-screen-api.service robot-back-screen-kiosk.service` |
| Pico 仅关闭网页，保留后端 | `sudo systemctl stop robot-back-screen-kiosk.service` |
| Pico 再次打开网页 | `sudo systemctl start robot-back-screen-kiosk.service` |
| Pico 刷新整个显示界面 | `sudo systemctl restart robot-back-screen-kiosk.service` |
| Pico 重启后端以加载新配置 | `sudo systemctl restart robot-back-screen-api.service` |
| Pico 同时重启前后端 | `sudo systemctl restart robot-back-screen-api.service robot-back-screen-kiosk.service` |
| Pico 关闭前后端 | `sudo systemctl stop robot-back-screen-kiosk.service robot-back-screen-api.service` |
| Orin 启动复位主控 | `sudo systemctl start robot-motion-supervisor.service` |
| Orin 重启复位主控 | `sudo systemctl restart robot-motion-supervisor.service` |

浏览器内可按 `Ctrl+R` 或 `F5` 刷新。浏览器由 systemd 自动拉起，按 `Alt+F4` 后可能再次打开；需要保持关闭时使用 `systemctl stop`。`stop` 只关闭本次运行，下次开机仍自启动。

Orin 主控重启后重新进入锁定流程，需要按实际状态重新进行人工复位和新任务确认。

### 开机自启动

安装脚本已对上述三个服务执行 `systemctl enable`，以后开机无需手动运行启动命令。

Pico 开机后先进入桌面，再打开网页。安装脚本在已有 `/etc/gdm3/custom.conf` 时配置 `nav01` 自动登录；屏幕启动脚本关闭 GNOME 自动锁屏、空闲息屏及 X11 屏保。当前配置适用于 GNOME/GDM、X11、UID 1000、`DISPLAY=:1`、浏览器路径 `/usr/lib/firefox/firefox`；换系统镜像后需按实际桌面会话调整 `deploy/robot-back-screen-kiosk.service`。

查看自启动配置：

```bash
# Pico
systemctl is-enabled robot-back-screen-api.service robot-back-screen-kiosk.service

# Orin
systemctl is-enabled robot-motion-supervisor.service
```

`enabled` 表示已启用自启动，是否正在运行用 `systemctl status` 查看。取消 Pico 网页自启动用 `sudo systemctl disable --now robot-back-screen-kiosk.service`，恢复用 `sudo systemctl enable --now robot-back-screen-kiosk.service`。

## 4. 如何打开网页

Pico 本机浏览器使用：

| 地址 | 用途 |
| --- | --- |
| `http://127.0.0.1:8000/` | 背屏页面 |
| `http://127.0.0.1:8000/monitor` | Orin/Pico 数据监控页，每 5 秒刷新 |
| `http://127.0.0.1:8000/docs` | HTTP 接口说明，包含 monitor 链接 |
| `http://127.0.0.1:8000/healthz` | 后端运行和数据接收状态 |

后端默认只监听 Pico 的 `127.0.0.1`。要在自己的电脑查看，将 `PICO_IP` 替换为 Pico 当前地址，建立 SSH 转发并保持终端开启：

```bash
ssh -N -L 18000:127.0.0.1:8000 nav01@PICO_IP
```

在自己电脑打开 `http://127.0.0.1:18000/`；监控页为 `http://127.0.0.1:18000/monitor`。此时自己电脑无需另外启动前端服务。

Pico 配置文件为 `/etc/robot-back-screen/env`，修改后重启 API。Orin 主控配置为 `/etc/robot-back-screen-motion/env`。具体话题及配置变量见 [数据与 topic 对照](backend/ROS_MAIN_FIELD_MAPPING.md)。

## 5. 页面如何使用

| 页面或按钮 | 操作与含义 |
| --- | --- |
| 状态 | 查看双电池、位置、速度、左右 TCP、关节、左右腕合力、计算资源和设备连接状态；Pico/Orin IP 分行展示 |
| 刷新诊断 | 根据当前已接入的数据重新检查，不会启动机器人运动 |
| 确认已恢复 | 重新确认已经恢复的告警，仍存在的故障不能强行清除 |
| 首页告警条 | 点击进入告警页，查看具体告警和处理建议 |
| 日志 | 查看 ROS `/rosout` 与后端操作记录，缓存最近 200 条，可导出 CSV |
| 作业总结 | 展示任务系统提供的记录；当前本地后端没有记录来源时显示 `--` 和“暂未接入作业记录” |
| 工具 → 3D 视图 | 拖动旋转、滚轮缩放；悬停高亮模型部位；关节数据驱动模型姿态 |
| 3D 信息框 | 运动、关节、电池、传感器可同时打开，按左上、右上、左下、右下排列；关闭后自动补位 |

电池、资源和关节等数值主要保留一位小数；位置、速度和 TCP 当前为后端格式化的两位小数字符串。`0.0` 表示收到数值零，不能单凭零值判断与实机一致；`--` 表示未接入、无有效值或消息已过期。相机绿灯表示存在发布者，不代表已检查图像内容。

`ROS-1`、`ROS-2`、`ROS-3` 通用诊断项不再显示，也不计入告警数量或影响首页健康状态。具体资源、设备离线及已接入的具体故障告警继续展示。默认异常持续 5 秒才进入实时告警列表，恢复后下次刷新自动移除。

### 急停后的复位

1. 按下实体急停后，显示“急停已触发，请释放按钮”，复位按钮置灰。
2. 物理释放急停，等待有效底盘状态与速度反馈。只有主控处于 `E_STOP_RELEASED`、已确认静止、运动链路和复位服务可用时，按钮才可点击并闪烁。
3. 点击“复位”，在页面内二次确认框选择“确认复位”。“取消”不会发送命令。
4. 处理中按钮置灰。成功服务回执与发送后的新鲜底盘反馈均到达后，自动显示复位完成，按钮保持灰色，无需再点击一次。

HTTP 返回“已受理”仅表示请求进入流程。默认复位超时 10 秒；失败时按页面提示处理。复位前会锁定运动、清空速度目标、记录旧任务中断并取消旧导航目标。复位完成不自动恢复旧任务，任务系统需人工确认新任务后重新下发。接口和状态说明见 [急停复位实现](backend/CHASSIS_RESET.md)。

## 6. 数据来源与常用查看命令

每项数据的 topic、消息类型和处理方式见 [数据与 topic 对照](backend/ROS_MAIN_FIELD_MAPPING.md)，包含 CPU、运行时长、续航、左右腕合力等计算数据和未接入字段。

Pico 终端混入 ROS1 环境时，先打开干净终端，再加载中间件查看数据：

```bash
env -i HOME="$HOME" USER="$USER" TERM="$TERM" \
  PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin \
  bash --noprofile --norc
source /etc/nav01/Middleware.env
source /opt/ros/humble/setup.bash
ros2 topic info -v /zj_humanoid/upperlimb/joint_states
ros2 topic echo --once /zj_humanoid/upperlimb/joint_states
```

Orin 加载 `/etc/naviai/Middleware.env`。话题前缀按实际 `ROBOT_NAME` / `ROS_NAMESPACE` 替换。只有话题名、没有实际消息，页面仍可能没有数据。

查看服务日志：

```bash
# Pico
journalctl -u robot-back-screen-api.service -u robot-back-screen-kiosk.service -n 60 --no-pager

# Orin
journalctl -u robot-motion-supervisor.service -n 60 --no-pager
```
