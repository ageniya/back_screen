# 背屏包核心文件说明

更新日期：2026-11-11。本文面向接手代码的人，说明重要文件负责什么、文件之间怎样配合，以及常见修改应该从哪里开始。下文路径均相对于仓库根目录。

实际启动、关闭和页面操作见 [背屏使用说明](背屏交付与使用手册.md)；每项数据的 topic、消息类型和字段含义见 [数据与 topic 对照](backend/ROS_MAIN_FIELD_MAPPING.md)。

## 1. 先看懂整体关系

```text
Pico / Orin 的 ROS2 话题
    ↓
robot_back_screen/services/telemetry.py       读取并整理原始数据
    ↓
robot_back_screen/services/unified_service.py 组合状态、具体告警和可选远端数据
    ↓
robot_back_screen/main.py                    提供 HTTP 接口和网页文件
    ↓
frontend/src/scripts/app.js                  请求数据、处理按钮、更新界面
    ↓
frontend/index.html + frontend/src/styles/app.css
```

Pico 运行后端和全屏浏览器，Orin 运行复位主控。Pico 通过 ROS2 网络读取 Orin 发布的话题，默认不要求 Orin 额外运行一个背屏 HTTP 后端。

## 2. 后端最重要的四个文件

| 文件 | 负责什么 | 通常什么时候修改 |
| --- | --- | --- |
| [main.py](../robot_back_screen/main.py) | 后端入口，定义 `/healthz`、`/api/v1/robot/snapshot`、`/api/v1/alarms`、`/monitor` 和控制请求等 HTTP 接口；托管构建后的前端网页 | 增加或修改 HTTP 接口、网页静态文件路径、跨域配置 |
| [telemetry.py](../robot_back_screen/services/telemetry.py) | 真正订阅 ROS2 话题，转换电池、关节、TCP、腕力、资源等消息；维护数据接收时间，清理过期读数；读取 Pico 本机资源、网卡和开机时长；把复位请求转交 Orin 主控 | topic 改名、消息类型或字段变化、新增数据接入、数据一直没有读到 |
| [unified_service.py](../robot_back_screen/services/unified_service.py) | 汇总状态、计算首页健康状态和告警数量，执行内置资源/离线诊断，过滤通用 `ROS-1/2/3` 告警；配置了远端 HTTP 时合并 Orin 数据 | 告警阈值、持续时间处理、告警过滤、Pico/Orin 数据合并规则 |
| [runtime_metrics.py](../robot_back_screen/services/runtime_metrics.py) | 根据有效电压、电量、电流推断充电状态；根据剩余 Ah 与滑动窗口平均放电电流估算续航，两组电池分别维护样本 | 电流方向、充电状态推断、续航计算规则 |

`telemetry.py` 决定“从哪里读、怎样转换”；`unified_service.py` 决定“怎样组合、产生哪些具体告警”；`main.py` 决定“网页通过哪个地址获取结果”。

运行时长来自 `telemetry.py` 读取的 `/proc/uptime`，不是 `runtime_metrics.py` 的任务计时器。当前作业总结本地接口仍返回空记录，页面具备展示逻辑不等于已经接入任务系统。

## 3. 前端最重要的几个文件

| 文件 | 负责什么 | 通常什么时候修改 |
| --- | --- | --- |
| [index.html](../frontend/index.html) | 页面骨架：状态、告警、日志、作业总结、工具、复位按钮和页面内二次确认框 | 增减显示字段、按钮或页面区域 |
| [app.js](../frontend/src/scripts/app.js) | 页面主要交互：定时请求数据、更新数值、切换页面、显示告警和日志、计算作业总结展示值；管理复位确认框及按钮状态、3D 信息框 | 数据已到后端但页面没有展示、点击不跳转、按钮行为、页面刷新频率 |
| [app.css](../frontend/src/styles/app.css) | 排版、颜色、字号、按钮状态、弹窗及不同屏幕尺寸的样式 | 数据溢出屏幕、未对齐、换行、界面尺寸适配 |
| [robot-viewer.js](../frontend/src/three/robot-viewer.js) | 用 Three.js 和 URDF 加载模型，处理旋转缩放、关节姿态、动作平滑、悬停高亮，以及打开/隐藏后的渲染恢复 | 3D 模型姿态、拖动缩放、高亮、渲染性能 |
| [robot-contract.js](../frontend/src/api/robot-contract.js) | 整理后端快照和作业总结字段，为缺失字段补默认结构，防止不完整数据直接破坏页面 | 后端字段结构变化、兼容新的数据返回格式 |
| [runtime-config.js](../frontend/public/runtime-config.js) | 确定网页请求哪个后端；支持 `?api=...`，正式部署默认使用同源 `/api/v1` | 需要改变网页连接的后端地址 |

模型源文件在 [frontend/public/models/](../frontend/public/models/)，包括 URDF 和 STL。更换模型需要同时关注关节名称、轴向和原点与真实状态数据的对应关系。

前端源码修改后需重新构建 `frontend/dist/`，再更新 Pico 上安装的网页文件。仅修改源码不会自动改变机器人上已经安装的页面。

## 4. 急停复位相关文件

```text
网页复位按钮及页面内二次确认
    → Pico main.py / telemetry.py
    → Orin /{ROBOT_NAME}/back_screen/reset
    → motion_supervisor.py
    → 运动锁定、任务取消、底盘 agv_reset、状态反馈
    → Pico 快照 → 页面自动更新按钮状态
```

| 文件 | 负责什么 |
| --- | --- |
| [motion_supervisor.py](../robot_back_screen/motion_supervisor.py) | Orin 主控入口，提供自己的复位与新任务确认服务，订阅底盘状态及里程计，取消导航目标，调用底盘复位，检查运动路由并发布 `reset_status` |
| [chassis_reset.py](../robot_back_screen/services/chassis_reset.py) | 复位状态机，处理急停按下/释放、静止和数据新鲜度条件、处理中防重复、成功/失败和超时；协调先后顺序不确定的服务回执与状态反馈 |
| [motion_gate.py](../robot_back_screen/services/motion_gate.py) | 保存运动锁定状态、速度目标与旧任务中断记录；锁定期间丢弃运动指令，人工确认新任务后才允许新的指令 |
| [motion_supervisor_stop.py](../robot_back_screen/motion_supervisor_stop.py) | systemd 停止主控后调用的辅助入口，向门控速度出口发送零速度 |

网页 `app.js` 只发请求和显示结果，真实复位条件由主控再次校验。修改按钮样式或显示文字不会改变底盘的复位条件。完整状态与接口见 [急停复位说明](backend/CHASSIS_RESET.md)。

## 5. 部署和启动文件

| 文件 | 用途 |
| --- | --- |
| [deploy/install.sh](../deploy/install.sh) | 一键安装入口，用 `pico` / `orin` 参数选择对应安装脚本 |
| [deploy/install-pico.sh](../deploy/install-pico.sh) | 安装 Pico 后端、构建后的网页和显示服务，备份旧文件、保留现有配置、启用自启动，并配置适用桌面环境的自动登录 |
| [deploy/install-motion-supervisor.sh](../deploy/install-motion-supervisor.sh) | 在 Orin 安装复位主控、调整实际底盘运动入口的重映射，并启用主控自启动 |
| [deploy/start.sh](../deploy/start.sh) | 手动一键启动已安装的 Pico 或 Orin 服务；它不是整套机器人中间件的启动入口 |
| [deploy/start-pico-api.sh](../deploy/start-pico-api.sh) | Pico API 的前台启动入口，加载中间件及 ROS 环境，再启动 Python 后端 |
| [deploy/start-pico-screen.sh](../deploy/start-pico-screen.sh) | 等待 API 和桌面就绪，关闭锁屏/息屏设置，使用 Firefox 全屏打开背屏 |
| [deploy/start-motion-supervisor.sh](../deploy/start-motion-supervisor.sh) | Orin 主控的启动入口，加载 ROS 环境；带 `stop` 参数时运行零速度辅助程序 |
| [robot-back-screen-api.service](../deploy/robot-back-screen-api.service)、[robot-back-screen-kiosk.service](../deploy/robot-back-screen-kiosk.service)、[robot-motion-supervisor.service](../deploy/robot-motion-supervisor.service) | systemd 托管配置，指定运行用户、配置文件、启动入口和重启策略；安装脚本启用它们的开机自启动 |

Pico 实际运行目录为 `/opt/robot-back-screen`，配置为 `/etc/robot-back-screen/env`；Orin 主控目录为 `/opt/robot-back-screen-control`，配置为 `/etc/robot-back-screen-motion/env`。编辑仓库文件之后，还需更新对应安装目录才能在机器人上生效。

[.env.example](../.env.example) 供查看可配置项，复制或编辑它不会自动改变 systemd 服务的配置。正式运行时以 `/etc/.../env` 的内容为准。

## 6. 其它按需查看的文件

| 文件或目录 | 作用 |
| --- | --- |
| [monitor_page.py](../robot_back_screen/monitor_page.py) | `/monitor` 数据监控页，分 Orin / Pico，每 5 秒刷新；它和背屏主界面的 `app.js` 是两套显示代码 |
| [clients/remote_robot.py](../robot_back_screen/clients/remote_robot.py) | 可选 Orin HTTP 客户端，仅设置 `ORIN_API_BASE` 时启用 |
| [clients/diagnosis_engine.py](../robot_back_screen/clients/diagnosis_engine.py) | 可选外部诊断引擎连接；`DIAGNOSIS_WS_URL` 留空时使用内置诊断 |
| [requirements.txt](../requirements.txt)、[frontend/package.json](../frontend/package.json)、[frontend/package-lock.json](../frontend/package-lock.json) | 后端 Python 依赖、前端依赖及前端版本锁定文件 |
| [package.xml](../package.xml)、[setup.py](../setup.py)、[setup.cfg](../setup.cfg)、[resource/robot_back_screen](../resource/robot_back_screen) | ROS2 包名、依赖、Python 程序入口、资源安装和 ament 包索引标记 |
| [launch/back_screen.launch.py](../launch/back_screen.launch.py) | 通过 ROS2 launch 启动 HTTP 后端的入口；不会一并启动屏幕浏览器和 Orin 主控 |
| [deploy/ros_interfaces/chassis_msgs/](../deploy/ros_interfaces/chassis_msgs/)、[build-chassis-interface.sh](../deploy/build-chassis-interface.sh) | Pico 缺少 `AGVNewState` 时构建私有消息解码接口；不包含底盘驱动 |
| [tests/](../tests/) | 状态机、主控边界、电池计算等开发测试，日常使用无需运行 |

`frontend/dist/`、`frontend/node_modules/`、`.venv/` 和 `__pycache__/` 是生成产物或本机依赖。修改业务应编辑对应源码，不直接修改依赖目录。独立的 `ros2_media_play/` 是视频播放功能，不属于背屏主界面的运行链路。

## 7. 常见需求从哪里改

| 要做的事 | 优先查看 |
| --- | --- |
| 增加一条真实 topic 或适配新消息类型 | `telemetry.py`；同步更新数据 topic 对照文档 |
| 修改 CPU 告警阈值或告警持续时间 | 正式配置中的 `ALARM_CPU_WARN_PERCENT` / `ALARM_PERSIST_SECONDS`；判断逻辑在 `unified_service.py` |
| 增加首页显示字段 | `index.html`、`app.js`，必要时改 `app.css`；确认后端已提供该字段 |
| 调整开机是否显示、桌面会话或浏览器路径 | `deploy/start-pico-screen.sh`、`deploy/robot-back-screen-kiosk.service` 及 Pico 安装脚本 |
| 调整复位超时或可用条件 | 主控配置 `ROS_RESET_TIMEOUT_SECONDS`、`chassis_reset.py`；ROS 操作顺序在 `motion_supervisor.py` |
| 修改作业总结 | 前端 `app.js` 的展示/计算逻辑，以及后端 `unified_service.py` / `telemetry.py` 的真实记录来源 |
| 修改监控页而非背屏页面 | `monitor_page.py` |
